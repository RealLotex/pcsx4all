# Internal polygon raster resolution prototype

This branch adds an experimental gpulib path, built with `make opk INTERNAL_RESOLUTION=1`. The graphics menu offers `Internal resolution: original / half / quarter / eighth`; saved settings default to original. Each step divides both polygon raster dimensions by 2, 4 or 8. It does not offer double resolution: that would increase the work, whereas these four levels target reduced rendering cost. A normal build leaves the experiment disabled.

This is a polygon raster resolution control, not vertex snapping or texture-coordinate quantization. It affects textured and Gouraud-shaded polygons. Flat untextured polygons, lines, sprites and native VRAM transfers retain their existing paths. There is no universal PS1 object/text classification. Do not claim that all text in every game is protected.

The scan converter receives reduced vertex coordinates and a reduced clipping rectangle. It therefore evaluates fewer scanlines and samples, then expands each covered sample into a native VRAM pixel block. Native VRAM transfers, saved-state layout and texture/CLUT addresses stay unchanged. Destination masks, blending, source mask bits, dithering and display pixel skipping are applied to native destination pixels. Texture-page/CLUT feedback falls back. Original PS1 maximum polygon dimensions are checked before the reduced-coordinate limit.

The new path accepts indexed alpha textures and 16-bit textures; it does not apply the palette-opacity exclusions used by the earlier quality controls. Sprites and common axis-aligned UI polygons bypass it. Arbitrary transformed text cannot be identified universally; broader font/compatibility verification remains necessary.

The host test compares 960 instantiated original shader paths at all three scales (2,880 cases) against the new native-pixel destination effects of shared coarse samples. All cases pass on the host, with ASan/UBSan and on MIPS/QEMU. It checks clipping, masks, all blending modes, dithering, indexed transparency, direct-color textures, UI bypass, feedback rejection, native polygon size limits and state restoration. Configuration round trips and malformed values also pass under MIPS/QEMU. A production triangle needed 7,720 raster samples at native resolution, 1,935 at half, 509 at quarter and 128 at eighth. These checks do not prove full PS1 GPU correctness or a hardware FPS gain.

The initial generic block writer was slower in a preliminary same-executable Gran Turismo/QEMU measurement (17.07 CPU seconds native, 31.45 half, 29.64 quarter for 1,500 output frames). That comparison was stopped after these samples; it is incomplete. Specialized opaque texture shaders with paired stores reduced that overhead. Before adding the menu and eighth scale, two runs each measured 16.92/17.11 CPU seconds native, 17.94/18.41 half and 15.87/16.09 quarter. Quarter used approximately 6.1% less CPU; half regressed by approximately 6.8%. These are local CPU-time measurements, not console FPS.

The comparison loads the same locally created High Speed Ring state (stationary car), HLE BIOS, NTSC, rec multiplier 2.0, frameskip off, no frame limit. It warms up for 500 output frames and measures through frame 2,000. The same executable selects the rendering mode. Replay/ISO alignment/JIT permission hooks exist only in the disposable QEMU build. `GPU_LOWRES_TEST_ENV` enables its `PCSX4ALL_RASTER_SHIFT` selector; neither those hooks nor that selector is in the production OPK. A limited screenshot check found all 1,431 selected orange HUD pixels unchanged at half and quarter in frame 2,000. It is not a test of every glyph or scene.

The delivered previous quality-control OPK produced no observed FPS improvement on the user's RS-97. This branch has no hardware measurement yet, and remains experimental.
